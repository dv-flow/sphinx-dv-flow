###############
Worked Example
###############

The pages below are generated by this extension from the fixture packages in
``tests/data``, using exactly the directives described in
:doc:`reference/directives`. They are part of the documentation *and* part of
the acceptance test: this build runs with ``-W``, so a directive that emits a
warning fails CI.

A root task
===========

``simple.run`` declares ``scope: root``, so it renders as a command-line
interface. Note the resolved ``--build`` default with the expression it came
from, the open value set on ``--backend``, and the parameters with no flag
listed with their ``-D`` form.

.. dvf:autotask:: simple.run
   :root: ../tests/data/simple

Library tasks
=============

The ``library`` package publishes five tasks. The three ``consumes`` cases are
the point: ``Compile`` declares one, ``Link`` inherits that declaration through
``uses:``, ``Report`` declares ``none``, and ``Publish`` declares nothing at all
and says so.

Inherited parameters
====================

``inherit.Leaf`` derives from a two-level chain and changes exactly one default
and one flag. Every row in its parameter table names the task that introduced
the parameter.

.. dvf:autotask:: inherit.Leaf

Extension points
================

An abstract task answers a third question: not "how do I run this" and not
"what do I get if I use this", but "how do I derive from this". Note that
``RunnableBase`` declares ``scope: root`` and still gets no command line —
it cannot be run, so offering one would be an invitation to an error.

Data types
==========

Most of a type page points the *other* way from the declarations: who produces
this, who consumes it, what derives from it. None of that is answerable from
the type itself.

Lifecycle
=========

Deprecated tasks are excluded from a package listing — a listing answers "what
can I use here", and a task nobody should use is a wrong answer. Their pages
still exist, so links from old flow files keep working and still carry the
banner.
